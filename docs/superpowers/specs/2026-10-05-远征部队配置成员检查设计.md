# 远征部队配置成员检查设计

## 目标

本丸后勤可以为远征部队一至五分别指定一组刀剑男士。派遣前检查当前队伍是否包含配置中的全部刀剑；多出的队员允许保留。存在缺员时，在当前队伍中编入缺少的刀剑，确认配置成员已经齐全后再继续远征派遣。

本设计只检查刀剑成员，不要求刀位完全一致，也不检查刀装、马匹或宝物。未配置成员名单的部队保持现有派遣行为。

## 已确认的流程约束

- 检查挂在 `E_MarkTeam1` 至 `E_MarkTeam5` 的 `next` 列表首位。
- 每队新增一个常驻入口 node，始终位于对应 `E_MarkTeamN.next` 首位；该 node 同时使用自定义识别和自定义动作。“派遣前校验编队”开关通过 `enabled` 控制五个 node 是否运行。各队配置为空时按检查通过处理。
- 检查使用 `inverse`：底层识别在队伍包含全部配置刀剑时返回成功，经 `inverse` 后 node 不命中并继续现有派遣链；缺少至少一把时 node 命中并进入当前部队的编入流程。
- 配置采用包含关系：配置名单是当前队伍成员的子集即可，额外成员不触发调整或移除。
- 部队一至五分别维护自己的刀名输入配置；用户只输入一把或多把刀剑名称，不填写刀装、马匹、宝物或其他编队数据。
- 多个刀名按输入顺序处理缺员；从一号位开始顺序寻找空位，队伍满员时从前往后替换不在配置名单中的成员，已在队中的配置成员保留。
- 新增“派遣前校验编队”滑块开关；仅开关开启时运行成员校验，建议默认关闭以保持升级前行为。
- 编入完成后必须重新确认配置成员齐全，确认后才能进入疲劳检查和派遣点击。
- 配置刀剑无法找到或确认、当前队伍无法可靠识别、编入结果无法确认时，输出包含原因的日志并结束整个后勤任务；不继续派遣，也不盲目重试。

## 当前实现背景

- `Expedition.json` 的五个 `E_MarkTeamN` 都由派遣日志动作标记队伍，后继为疲劳检查与 `E_StartExpedition`。
- `E_StartExpedition` 识别并点击远征按钮。按本次决定，成员检查更早地挂在每个 `E_MarkTeamN` 的首个后继，检查通过时既有疲劳检查和派遣后继仍按原顺序执行。
- `interface.json` 的“部队一”至“部队五”当前用于选择远征地图，各自位于“远征”选项的齿轮配置中。
- “派遣前校验编队”滑块放在远征设置页顶部，统一控制五队检查；默认关闭。五队名单输入项始终显示并可编辑，切换开关不清空名单。
- “长期远征计划”启用 case 会覆盖五个 `E_MarkTeamN.next`。实施时必须同步在这五个 override 列表首位加入对应检查 node，否则启用长期计划后会绕过成员检查。
- 成员检查 node 保持在五个 `E_MarkTeamN.next` 首位；总开关通过对应 `E_CheckConfiguredMembersN.enabled` 控制其是否执行。`interface.json` 的开关关闭 case 显式关闭五个检查 node，开启 case 显式开启五个检查 node；长期远征计划对 `next` 的 override 也必须保留首位检查 node。
- 项目已有自定编队预设，存储六个位置的刀剑和其他装备信息；已有编队任务流程，但目前没有供后勤远征直接使用的成员子集检查和缺员补入链。
- 2026-10-04 的长期远征计划设计把用户维护远征刀剑名单列为非目标。本需求是新增且范围独立的配置能力；实施时需更新相关设计文档中的冲突描述，不能沿用该非目标限制。

## 建议设计

### 配置来源

在远征设置页顶部新增“派遣前校验编队”滑块，控制五支远征部队的成员校验，默认关闭。开关关闭时不执行检查，完全沿用现有派遣流程；开启时才检查已经填写名单的部队。关闭开关不清空配置，名单输入项仍显示且可编辑，用户可以先完成配置再开启检查。

在部队一至五各自的远征地图设置旁提供独立的刀名输入项，内容只表示该队必须包含的刀剑名单，不关联自定编队预设。允许输入一把或多把刀剑名称，多个名称使用顿号 `、` 分隔。空白输入表示该队没有校验目标，即使总开关开启也沿用旧行为。

设置页说明文案表达成员规则：“名单中的刀剑都在队伍中即可；缺少时会从一号位开始依次编入，队伍满员时替换额外成员。”输入示例使用“加州清光、歌仙兼定”。

配置解析应去除首尾空白、忽略空项，并拒绝无法识别的刀名，避免拼写错误被当作有效目标而意外放行或进入无法完成的编队流程。五支部队各自保存配置，修改一队不影响其他队。

### 首位检查 node 与分流

每个 `E_MarkTeamN` 的 `next` 首位加入对应入口 node，例如 `E_CheckConfiguredMembers1`。每个 node 同时声明自定义识别与自定义动作，并通过参数绑定队伍编号。自定义识别读取该队当前队员和配置名单；自定义动作在识别发现缺员时执行完整编队流程。

成员检查使用用户提供的 1280×720 远征“部队选择”页面。检查 node 使用自定义识别动作，分别 OCR 六个队员槽位的精确区域，再将识别出的非空刀名与该队输入配置做包含关系比较。六个 ROI 为 `[575,180,217,31]`、`[575,276,217,31]`、`[575,369,218,32]`、`[576,464,217,32]`、`[576,558,217,32]`、`[576,654,217,32]`。空槽位不构成成员；额外队员不影响通过结果。

该页面一至六号位“替换”按钮的点击区域如下：

| 位置 | 点击区域 |
| --- | --- |
| 一号位 | `[1020,140,33,58]` |
| 二号位 | `[1021,236,33,57]` |
| 三号位 | `[1020,331,32,57]` |
| 四号位 | `[1020,425,32,58]` |
| 五号位 | `[1019,519,33,58]` |
| 六号位 | `[1020,614,33,58]` |

1. 当前队员包含所有配置成员：识别成功，受 `inverse` 反转后检查 node 不命中，MaaFramework 继续尝试该 `next` 列表中的疲劳检查和派遣 node。
2. 当前队员缺少配置成员：识别失败，受 `inverse` 反转后入口 node 命中并执行完整编队自定义动作。
3. 当前队员名单无法可靠读取，或配置无法解析：不得把不确定状态当作通过；输出原因日志并结束整个后勤任务。

只要自定义识别发现缺员，入口 node 就命中并执行其自定义动作，不因队伍满员而跳过。由于 `inverse` 也会使 OCR 未命中或识别异常时触发该动作，动作必须在任何点击或队伍变更前重新确认当前页面、六个槽位 OCR 与名单解析结果；无法确认时输出日志并结束整个后勤任务。确认确实缺员后，动作按输入名单顺序逐一处理缺员，从一号位开始依次查找空位，优先使用空位；满员时从前往后替换不属于配置名单的额外队员，已在队中的配置成员应保留。动作在编入结束前复核全部配置成员，只有复核通过并报告动作成功，流程才继续疲劳检查与 `E_StartExpedition`。

### 编入流程

完整编队过程由入口 node 的单个自定义动作承担：从当前远征队伍页面原地进入编队操作，按配置名单处理缺员，执行选刀、确认和结束复核，并在动作成功后回到远征派遣链。自定义识别负责六个队员槽位的 OCR 与包含判断；自定义动作负责根据当前队伍和名单完成编入，不拆成多个 pipeline node 或多个 custom action。

刀剑选择流程参考 `FormationConfig.json` 中从 `FC_IsSwordSelect1` 开始的既有编队流程，并按远征场景动态适配。筛选弹窗中的“等级”指排序依据“刀剑等级”，与降序排序配合使用，不代表初／极筛选：

1. 点击目标槽位的“替换”后，确认进入“刀剑男士选择”页面。
2. 检查排序状态；若当前不是降序，切换为降序后确认状态已更新。
3. 打开“筛选”，先点击“取消筛选”清除旧条件，再依据刀名对应的刀种选择筛选项，并将排序依据设为“刀剑等级”。刀名到刀种的映射优先复用 `SwordBookCatalog.json` 与现有 `FormationFilterClickAction`。
4. 点击筛选页“确定”，确认已退出筛选页面后才开始查找目标刀名。
5. 使用现有 `ListOcrScan` 的精确刀名匹配与滚动扫描逻辑查找目标；当前列表没有命中时向下滚动并继续查找，直至找到或确认列表已到底。确认到底仍未找到时按失败策略处理并结束任务。
6. 选择目标刀剑并点击该行“确定”，返回入口 node 所在的远征“部队选择”页面；重新 OCR 六个位置，确认对应槽位已更新。
7. 若仍有配置刀剑缺失，则继续下一把；所有配置成员确认齐全后，自定义动作成功并回到疲劳检查与派遣流程。

用户已提供刀剑选择列表和筛选弹窗截图，并明确了操作顺序。实现时复用 `FormationConfig.json` 从 `FC_IsSwordSelect1` 起的排序、筛选与搜索组织方式，以及 `FormationFindSwordAction` / `ListOcrScan` 的刀名扫描能力；将固定槽位配置改为本次缺员名单，并把未找到、不可选等情况改为输出日志并结束整个后勤任务。实际页面若与现有参考参数不同，再按 1280×720 画面核对调整。

使用单个自定义动作的原因是缺员数量与名单内容在运行时变化，动作需要按队伍配置逐一处理缺员、通过 OCR 列表查找刀剑、按槽位状态决定使用空位或替换额外队员，并在同一流程中确认每次选择和最终队伍状态。把这些状态分支拆为固定 pipeline node 会形成大量重复组合，且难以保持“保留已匹配成员、从一号位顺序找槽”的行为一致。自定义动作仍须逐步识别当前界面和操作结果，不得用连续盲点、固定等待或失败重试代替确认。

当前远征成员页、六个槽位 OCR 区域、六个替换按钮区域、刀剑选择页、筛选弹窗，以及选择刀剑确认后返回入口页面的结果已提供。实现阶段沿用现有编队的筛选与列表扫描能力，并对照实际 1280×720 页面核验参数。

## 数据流

1. 任务配置提供总开关及部队一至五各自的可选刀名输入项。
2. 总开关关闭时，五个检查 node 均禁用；开启时，配置非空的部队才进入成员检查。
3. `E_MarkTeamN` 标记本次候选队伍后，其首个后继检查 node 获取队伍编号和对应配置。
4. 自定义识别对当前队员与目标名单执行集合包含判断。
5. 无缺员则由 `inverse` 使入口 node 不命中，进入既有疲劳检查和派遣流程。
6. 有缺员则入口 node 命中，其自定义动作按序编入缺员并确认操作结果。
7. 自定义动作复核通过后继续原有疲劳和派遣流程；复核失败或状态不明时输出原因日志并结束整个后勤任务，不得触发派遣。

## 失败处理与边界

| 情况 | 处理 |
| --- | --- |
| 未配置成员名单 | 检查视为通过，沿用原流程 |
| 配置名单全部已在队中 | 不进入编队，继续疲劳检查 |
| 有配置成员缺失且队伍未满 | 从一号位开始查找空位，依次编入缺员 |
| 有配置成员缺失且队伍已满 | 从一号位开始查找不属于配置名单的队员并依次替换为缺员；已满足配置的成员保留 |
| 当前成员 OCR 不完整或队伍页面不符 | 输出原因日志并结束整个后勤任务 |
| 配置为空 | 不做成员改动 |
| 输入包含无法识别的刀名 | 输出原因日志并结束整个后勤任务，提示需要修正名单 |
| 目标刀剑无法找到、不可用或编入未确认 | 输出原因日志并结束整个后勤任务，不继续点击远征 |
| 编入后复核仍缺员 | 输出原因日志并结束整个后勤任务；不得循环反复编入掩盖识别或操作失败 |

错误出口需遵循项目约束：只有开发者明确指定 node 的 `on_error` 时才增加该字段。成员校验或编入失败时应通过项目已有的结束当前任务能力结束整个后勤任务，避免误入 `E_StartExpedition`。

## 影响范围预估

实现阶段预计涉及：

- `assets/interface.json`：新增总开关、五个独立刀名输入项及对应 node 启停配置，并更新“长期远征计划”对五个 `E_MarkTeamN.next` 的 override，保证检查 node 在所有运行配置下都处于首位。
- `assets/resource/base/pipeline/Expedition.json`：五个 `E_MarkTeamN.next` 首位增加常驻检查 node，并定义缺员编入和复核流程。
- `_src/MFAAvalonia/Extensions/MaaFW/Custom/`：新增职责明确的自定义识别类与一个承担完整编队流程的自定义动作类，每类单独文件。
- `docs/复用节点清单.md`：登记新增的跨任务公共接口（仅当设计确认需要跨文件复用时）。
- `docs/upstream-customizations.md` 与 `docs/upstream-customizations.json`：若实施触及 `_src/` 并形成对 MFAAvalonia 上游行为的定制，同步记录。
- `docs/superpowers/specs/2026-10-04-long-term-expedition-formations-design.md`：修正与本需求冲突的非目标或成员检查描述，保留长期远征刷花本身的既有设计。

资源版本预估为 MINOR：新增远征成员配置、检查和编入逻辑属于用户可见的资源流程扩展。最终版本号应按实际改动范围和发布约定确定。

## 验收场景

- 总开关关闭：五支部队都不检查名单，远征行为和现有派遣顺序不变；名单仍显示、可编辑且保留。
- 总开关开启但某队名单为空：该队不检查名单，其余有名单的队伍正常检查。
- 默认配置：升级后总开关为关闭，避免改变已有用户的派遣行为。
- 未配置目标成员：远征任务按当前行为继续。
- 配置成员均在队伍中：检查 node 因 `inverse` 不命中，疲劳检查与派遣顺序不变。
- 配置成员只缺一部分：从一号位开始依次补入缺员，已经在队中的配置成员保留。
- 配置成员全部缺失：按配置逐一编入并确认。
- 队伍满员且缺少配置成员：不跳过；从一号位开始依次替换额外队员以补齐配置。
- 编入后确认配置成员均存在：继续原远征流程。
- OCR 漏识、选刀失败、确认失败或配置无效：输出原因日志并结束整个后勤任务，不得抵达远征按钮点击。
- 多队派遣时，每个检查只读取对应 `E_MarkTeamN` 的队伍配置，不串用其他队伍配置。
